# V1.3.3 学院情景库框架修正版更新说明

## 一、更新背景

V1.3.2 将学院模式过度收窄为“过敏性休克抢救教学模块”。本版修正为：

> 学院模式保留通用情景库框架；当前情景库中暂时只开放“严重过敏反应/过敏性休克抢救”一个情景。

也就是说，本版不是扩展新病例，而是把系统结构调回更适合后续拓展的设计。

## 二、核心原则

1. 基础引擎不变；
2. 临床模式不动；
3. 学院模式增加“情景选择页”；
4. 当前只开放一个情景；
5. 数据结构提前保留多情景扩展字段。

## 三、学院模式流程

```text
学院模式
↓
护理基础能力情景库
↓
选择教学情景
↓
在校护生信息登记
↓
课前测评 / 模拟训练 / 课后考核
```

当前开放情景：

| 字段 | 内容 |
|---|---|
| academy_scenario_id | academy_anaphylaxis_rescue |
| 情景名称 | 严重过敏反应/过敏性休克抢救 |
| 情景类别 | 急救护理 |
| 适用课程 | 基础护理/急救护理/儿科护理 |
| 难度层级 | 基础版 |
| 开放状态 | 已开放 |

## 四、新增导出字段

学院模式数据新增：

- `academy_scenario_id`
- `academy_scenario_name`
- `academy_scenario_category`
- `academy_course_type`
- `academy_difficulty`

这些字段进入训练报告、汇总记录、操作明细和一人一行配对分析结果。

## 五、配对分析调整

原分组逻辑：

```text
system_mode + participant_id + collection_mode
```

V1.3.3 调整为：

```text
system_mode + academy_scenario_id + participant_id + collection_mode
```

这样未来即使同一个护生完成多个学院情景，也不会把不同情景的课前、训练、课后数据混在一起。

## 六、当前未做的事

本版没有新增低血糖、跌倒、输液反应、气道梗阻等新场景。

本版只是先把“情景库框架”搭好，当前仍然只跑“严重过敏反应/过敏性休克抢救”这一项。
