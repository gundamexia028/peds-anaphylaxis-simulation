# V1.3.4 推广版权限与学院流程增强版

## 版本定位

本版本以 V1.3.3 学院情景库框架版为底座，继续保持临床基础引擎和临床模式评分逻辑不变，重点增强学院模式研究流程与管理者后台推广能力。

## 核心原则

1. 基础引擎不变。
2. 临床模式不改变原 V1.2.11/V1.3.3 的正式采集、三阶段质控、导出逻辑。
3. 学院模式保留“护理基础能力情景库”框架，目前仅开放“严重过敏反应/过敏性休克抢救”情景。
4. 管理者后台采用“总管理员 + 单位管理码”的推广版权限方案，单位管理员只能查看和导出本单位数据。

## 已合并的讨论定稿内容

### 1. 学院模式研究定位

采用“系统构建与初步应用效果评价的混合型研究”定位：

- 主线：课前测评与课后考核比较，评价护生能力提升。
- 辅线：SUS系统可用性问卷与教学体验问卷，评价系统可用性、学习体验与推广可行性。

### 2. 学院模式学习阶段简化

学习阶段调整为：

- 一年级
- 二年级
- 三年级
- 四年级
- 实习结束/毕业前

分析时可将一年级至四年级合并为“未系统临床接触组”，将“实习结束/毕业前”作为“已完成临床实习组”。

### 3. 学院模式测评按钮防提示

学院模式课前测评/课后考核采用中性操作标签，避免按钮泄题。例如：

- “识别疑似严重过敏反应/过敏性休克危险信号”在测评界面显示为“判断当前异常情况”。
- “准备抢救车、肾上腺素等急救药物并配合核对”在测评界面显示为“准备急救物品及相关药物”。
- 训练模式仍保留教学性标签与提示。

### 4. SUS与教学体验问卷整合进学院模式

学院模式课后考核结束后，系统进入课后评价页：

1. SUS系统可用性问卷（10条，5级评分，自动换算0–100分）。
2. 虚拟仿真教学体验问卷（8条，5级评分，自动计算总分和均分）。

问卷数据与课后考核报告绑定，不再依赖外部问卷星匹配。

### 5. 临床登记端医院全称字段

临床模式新增“医院全称”字段：

- 默认值：四川大学华西第二医院
- 前端提示务必填写医院全称
- 后续增加医院时可自由输入

### 6. 管理者后台推广版权限

后台支持两类进入方式：

- 总管理员密码：可查看全部数据，并可维护单位管理码。
- 单位管理码：只查看和导出绑定单位数据。

单位管理码分为：

- 临床单位管理码：绑定医院全称 + 科室全称。
- 学院单位管理码：绑定院校全称。

总管理员可在后台新增单位并生成管理码。系统保存管理码哈希值，只在生成时显示一次明文码。
